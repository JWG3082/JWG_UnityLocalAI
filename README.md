# Unity Local AI

**Unity Editor에서 로컬 LLM(Ollama)을 활용하는 개인용 Unity 개발 보조 도구입니다.**  
자연어로 Unity C# 코드를 질문·분석·수정하고, 현재 프로젝트와 활성 씬의 구성을 조사할 수 있습니다.

> **개발 상태:** 개인용 실험 프로젝트입니다. 자동화된 빌드·컴파일·플레이 모드 검증까지 완료된 제품은 아닙니다. GitHub 버전 번호는 저장소 소유자가 릴리스할 때 관리합니다.

## 현재 구현된 기능

### 1. 일반 채팅

- Ollama 로컬 모델과 Unity Editor 안에서 대화
- **자유 대화 / Unity C# / 게임 기획** 응답 유형 선택
- 응답 대기 활동 표시, 경과 시간 표시, 응답창 스크롤·복사
- 최근 작업의 완료 시각, 소요 시간 및 성공/실패 상태 표시

### 2. C# 코드 분석 — 읽기 전용

- Project 창의 `.cs` 파일 선택
- 인식된 **함수/메서드 단위 분석** 또는 파일 전체의 구성 요약
- 코드 역할, 중복 가능성, 잠재적 버그, 개선 방향 및 확인할 참조 관계에 대한 AI 피드백
- 분석만 수행하며 원본 스크립트를 변경하지 않음

### 3. C# 코드 수정 — 수동 승인

- **함수/메서드 선택(권장) / 줄 범위 선택 / 전체 파일** 중 수정 범위 지정
- AI가 수정안을 생성하고 **원본 / 수정안 / 변경 비교** 제공
- 변경 내용·이유·주의사항·Unity 테스트 방법에 대한 피드백 제공
- 사용자가 승인해야 파일을 적용하며, 적용 전 백업 저장
- 마지막 백업으로 복구하는 기능 제공
- 긴 코드는 전체 재출력 대신 원본과 **정확히 일치하는 SEARCH/REPLACE 패치** 방식 사용
- 패치가 원본과 일치하지 않으면 적용 차단

**용량 및 범위 관련 제한**

| 항목 | 현재 코드상의 상한 또는 동작 |
| --- | --- |
| 로컬 스크립트 읽기 | 최대 **200,000자** |
| 전체 파일 수정 대상 | 최대 **50,000자** |
| 선택 함수·줄 범위 수정 대상 | 최대 **50,000자** |
| 직접 코드 재작성 | 최대 12,000자; 초과 시 정확한 코드 검색·교체 방식 사용 |
| AI 컨텍스트 설정 | 8K / 16K / 32K 선택 |

> **50,000자 지원은 입력·수정 대상 크기의 상한입니다.** 모델이 50,000자를 모두 정확히 이해하거나 모든 패치를 성공시키는 것을 보장하지 않습니다. 큰 파일은 함수 단위로 나누어 작업하는 것이 안전합니다.

### 4. 프로젝트 기본 구조 스캔 — 읽기 전용

- 현재 Unity 프로젝트의 Assets 폴더 및 에셋 유형 집계
- 씬·스크립트·프리팹·asmdef 등의 경로 목록
- `Packages/manifest.json`의 직접 패키지 의존성 확인
- 구조 보고서 복사 및 선택적으로 로컬 LLM 설명 요청

### 5. 활성 씬 1개 상세 분석 — 읽기 전용

- **현재 열려 있는 활성 씬 한 개**를 대상으로 조사
- Hierarchy의 GameObject 계층 및 활성 상태
- 부착된 컴포넌트와 MonoBehaviour 스크립트
- Inspector에 직렬화된 오브젝트 참조 관계
- UnityEvent에 저장된 콜백 정보와 Missing Script 위치
- 씬 에셋의 프리팹·스크립트·머티리얼 등 의존성 조사
- 결과 보고서 및 필요 시 Granite 기반 해설

활성 씬 분석은 **편집 모드**에서 실행하며 다른 씬을 자동으로 열거나 저장하지 않습니다. 동적 `Addressables` 로딩, `GetComponent()` 탐색, 런타임 생성 객체, 실제 메서드 호출 경로는 정적 스캔만으로 완전히 확인할 수 없습니다.

## 요구 사항

- **Unity Editor** (Unity 6 기준으로 개발 및 테스트 중)
- **Ollama** 실행 중: 기본 주소 `http://localhost:11434`
- 기본 모델 **`granite3.3:8b`** (IBM Granite 3.3 8B)
- 모델 실행에 충분한 RAM·GPU 메모리; 긴 컨텍스트는 추가 자원을 사용합니다.

## 설치 및 사용

1. [Ollama 공식 다운로드](https://ollama.com/download)에서 Ollama를 설치하고 실행합니다.
2. CMD 또는 PowerShell에서 모델을 내려받습니다.

   ```powershell
   ollama pull granite3.3:8b
   ollama list
   ```

3. 이 저장소의 `Assets/Editor/UnityLocalAI.cs`를 사용할 Unity 프로젝트의 **`Assets/Editor/`** 폴더로 복사합니다. `Editor` 폴더가 없으면 생성합니다.
4. 같은 이름의 클래스가 이미 있다면 기존 파일을 먼저 백업하고 중복되지 않게 정리합니다.
5. Unity가 컴파일을 마치면 상단 메뉴 **Tools → Unity Local AI**를 실행합니다.
6. `일반 채팅`, `C# 작업`, `프로젝트 구조` 중 원하는 기능을 선택합니다.

**다른 PC에서 사용하기:** GitHub Private 저장소에 접근 가능한 계정으로 ZIP을 내려받거나 `git clone`하고, 해당 PC에도 Ollama와 모델을 설치해야 합니다. 모델 가중치는 이 저장소에 포함되어 있지 않습니다.

## 모델·성능 관련 참고

- 현재 스크립트의 기본 모델은 `granite3.3:8b`입니다. 다른 Ollama 모델을 시험하려면 `UnityLocalAI.cs`의 `ModelName`을 바꾸고 해당 모델을 다운로드해야 합니다.
- 모델별 Unity API 정확도, 한국어 설명, 코드 수정 성공률, 응답 시간은 다릅니다.
- RTX 3070 8GB에서는 32K 컨텍스트가 느리거나 메모리 부족을 유발할 수 있습니다. 필요하면 8K 또는 16K로 조정하고 분석 범위를 줄이세요.
- 진행 바는 **실제 완료율이 아닌 활동 표시**입니다. 별도로 경과 시간을 기록합니다.

## 안전 및 알려진 제한 사항

- **코드 수정은 수동 승인 방식**입니다. 승인 전에는 파일을 덮어쓰지 않습니다.
- 백업은 Unity 프로젝트의 **`Library/UnityLocalAIBackups/`**에 저장됩니다. `Library`를 삭제하면 백업이 소실될 수 있으므로 중요한 변경 전에는 Git 커밋 등 별도 백업을 권장합니다.
- 함수 목록은 간이 C# 구문 분석을 사용하므로 일부 제네릭·식 본문 메서드 등에서 추출이 부정확할 수 있습니다. 필요 시 줄 범위 선택을 사용하세요.
- Granite의 코드·분석 결과는 **제안 사항**입니다. 적용 후 반드시 Console 컴파일 오류, Inspector 참조 및 Play Mode 동작을 확인하세요.
- AI가 컴파일·플레이 테스트를 자동 수행하거나 오류를 자동 수정하는 기능은 **아직 구현하지 않았습니다.**
- 씬/프로젝트 보고서는 일부 항목에 스캔·출력 개수 제한이 있으며, 로컬 LLM에 전달되는 내용은 보고서의 요약본일 수 있습니다.
- 로컬 API 사용을 전제로 설계되었습니다. Ollama의 Cloud/외부 연결 설정을 별도로 확인하세요.
- 회사·고객 프로젝트의 소스, 자격 증명, 비밀키 등은 허가 없이 저장소에 올리지 마세요. Private 저장소라도 기본 보안 수칙을 지켜야 합니다.

## 향후 작업 계획 (미구현)

1. **씬 GameObject 조작:** 자연어로 오브젝트 생성·이동·회전·크기 변경, 미리보기·승인·Undo 지원
2. **이미지 생성:** 별도 로컬 이미지 생성 엔진과 연동하고 Unity 에셋으로 가져오기
3. **Addressables 등 Unity 자동화:** 에셋 등록·설정·로딩 및 Release 검증부터 단계적 확장
4. **Unity Local AI 지식 고도화:** Unity 공식 최신 문서, 개인 개발 노하우, 프로젝트별 지식을 검색·활용하는 RAG, 모델 성능 비교 및 피드백 축적 연구

> 위 네 항목은 **예정 기능**이며 현재 코드에 구현되어 있지 않습니다. 기능 개발 중에는 버전 번호를 임의로 올리지 않고, GitHub 반영 시점에 소유자가 결정합니다.
